## 세부 작업 내용

### 1. 멀티 async 비동기 처리 테스트

- 여러 비동기 요청 또는 처리 작업이 동시에 수행되는 상황을 기준으로 테스트를 진행했다.
- 비동기 작업 간 충돌, 순서 의존성, 응답 누락 가능성을 확인했다.
- 병렬 처리 이후 결과 수집 및 상태 반영 흐름을 점검했다.

### 2. 보안사항 체크 및 반영

- 보안 관련 점검 항목을 리스트로 정리했다.
- 코드, 설정, 데이터 처리 흐름에서 확인이 필요한 항목을 검토했다.
- 확인된 보완 사항을 반영하고, 추후 재검토할 수 있도록 문서화했다.

### 3. 프롬프트 가드레일 점검

- 사용자 입력 프롬프트와 내부 생성 프롬프트의 처리 흐름을 점검했다.
- 부적절하거나 위험한 입력이 생성 파이프라인에 전달되지 않도록 가드레일 기준을 확인했다.
- 최종 프롬프트 빌더와 연결되는 제한 조건 및 보강 포인트를 정리했다.

### 4. 테스트 리스트 정리 및 문서화

- 현재 적용된 기능 기준으로 필요한 테스트 리스트를 정리했다.
- 비동기 처리, 보안, 프롬프트, 비디오 라우터, 참조 이미지 처리 항목을 테스트 범위에 포함했다.
- 테스트 항목별 확인 여부와 문서화 상태를 구분했다.

### 5. 비디오 라우터 Runway 추가 여부 결정 및 반영

- 비디오 생성 라우터에 Runway를 추가할지 검토했다.
- 기존 비디오 생성 흐름과의 호환성, 라우팅 기준, 후속 확장 가능성을 기준으로 판단했다.
- 결정된 방향에 따라 관련 코드를 작성하고 문서화했다.

### 6. 비디오 참조 이미지 테스트 및 프롬프트 빌더 보강

- 비디오 생성 과정에서 참조 이미지가 정상적으로 전달되고 활용되는지 테스트했다.
- 참조 이미지가 포함되는 경우 최종 프롬프트가 더 명확하게 구성되도록 프롬프트 빌더를 보강했다.
- 수정된 프롬프트 빌더 기준으로 최종 프롬프트 생성 흐름을 확인했다.

## 후속 확인 사항

- Runway 라우터 적용 이후 실제 생성 요청 기준의 예외 케이스를 추가 점검한다.
- 참조 이미지가 없는 경우와 있는 경우의 최종 프롬프트 차이를 샘플로 남긴다.
- 보안사항과 프롬프트 가드레일 문서는 기능 변경 시 함께 업데이트한다.
- 테스트 리스트는 기능 추가 시 체크리스트 형태로 계속 확장한다.
